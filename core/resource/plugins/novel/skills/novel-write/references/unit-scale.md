# 单元规模控制

单元是小说生产的原子单位：一次矛盾，从起到收。规模太大 → CONTEXT 爆炸、章间钩子断裂、一次写不完；太小 → 因果不完整、爽点密度不够。

怎么切（幕、章内场景）在规划技能 `novel-plan/references/outline.md`「怎么切单元」。本文件只守规模数字。卷的幕是卷纲节奏锚点，不是单元的别名；章内可写单位在细纲里叫场面，不另建场景层。

## 默认规模

| 维度 | 默认值 | 硬上限 |
|------|--------|--------|
| 单元章数 | 3–8 章 | **10 章**（超过必须拆单元） |
| 单章字数 | 2000–3500（runes） | 3500 |
| 单章字数地板 | 2000 | precommit 硬检 |
| 单元总字数 | 章数 × 2500 ± 20% | 章数 × 3500 |

## 什么时候用短单元（2–3 章）

- **高密度爽点**：打脸/翻案/小高潮，不需要长铺垫。
- **卷末收束**：一卷最后一个单元，短一点利于收束情绪和埋卷间钩。
- **过渡单元**：换地图/换队伍，用短单元快速过场。
- **死局预演/危机单元**：时间紧迫感强，2–3 章内闭环。

## 什么时候用长单元（6–8 章）

- **主线大案**：8 年连环案、跨省追凶、收网正戏——需要走访/审讯/复勘多轮。
- **感情摊牌/大吵**：情绪曲线长，需要铺垫→爆发→余波。
- **升级台阶**：调岗/比武/封神，需要立威+打脸+余波。

## 禁止

- **单单元 >10 章**：gate 硬检 FAIL。遇到必须拆成两个单元（如 U3a/U3b，或 U3/U4），中间加一个"兑现/余波"节。
- **单单元 <2 章**：一次矛盾从起到收至少需要"建立期待+尝试+加压+决断+兑现"五个节拍，2 章塞不下（除非是极短过渡单元，需在 yaml 标注 `unit_type: transition`）。
- **一单元一爽点**：长单元（>5 章）至少 2 个爽点（小爽+大爽），否则中段疲软。
- **字数后验补救**：word_floor 在 precommit 硬检，低于地板直接 FAIL，不允许"写完再扩"。

## 与卷纲索引的配合

卷纲单元索引表的"章范围"决定单元规模。规划时：

1. 先按"一次矛盾从起到收"切单元，不要按章数凑。
2. 切完数一下章数：落在 3–8 章最好；>10 章必拆；<3 章问自己"这是不是另一个单元的余波"。
3. 卷纲索引表填章范围时，gate 会校验：连续无缺口、覆盖本卷全部章、单单元 ≤10 章。

## 字数地板/天花板怎么填

yaml 里：

```yaml
word_target: 12500   # 各章 word_share 之和
word_floor: 10000   # = 章数 × 2000（硬下限）
word_ceiling: 14000 # = 章数 × 3500（硬上限）
```

precommit 实测单元 runes 数：
- < word_floor → FAIL（"字数不足，先扩写"）
- > word_ceiling → WARN（"字数超标，考虑拆单元或收紧场面"）
- 区间内 → PASS

不要在 Commit 日志里手写"逐章扩写至 X runes"——gate 会自动报告实测数。
