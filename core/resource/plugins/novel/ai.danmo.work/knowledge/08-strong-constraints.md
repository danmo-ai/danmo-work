# 强约束

每章写前/审稿勾选；章纲字段 `constraint_checks` 镜像。读者契约与终局储备写在圣经 / 总纲，本篇是判定，不是第二套大纲。

## 读者契约

开篇、题材、主角配置共同许诺的阅读快感。先问：读者是来看主角解决问题、看群像、看导师托举，还是看制度合作？契约不同，同一情节风险不同。

**主角代理权 = 因果权 + 结算权**（不看出场时长，不要求事事亲手）：

1. 谁决定事情为什么发生 / 如何进入？
2. 谁作出不可替代的关键选择？
3. 谁承担或选择关键后果？
4. 核心收益 / 认可 / 权力结算给谁？

配角可执行局部动作，不得无声夺走已承诺的高光。核心资产（金手指、关键证据、身份底牌）不得无交换上交机构。

| 等级 | 定义 | 处理 |
|------|------|------|
| 契约安全 | 与开篇一致；选择与收益清楚 | 可写，交换须可见 |
| 需补强 | 稀释高光或推进过快，能用铺垫/代价修好 | 写前补理由或改成阶段性兑现 |
| 契约破坏 | 没收卖点；无关角色夺走期待所有权；无交换接管核心资产 | 修纲，不得定稿 |

## 期待债

每次承诺（会反击、会升级、会揭身份、会推进感情）都欠一笔债。可以延期，但要付利息：阶段性进展、新信息、局势变化或更清晰的下一目标。用设定解说拖延 = 合理化债务，解释本身吞掉爽点则先砍解释。

换地图 / 新机构 / 新能力 / 新敌人会**新增**期待债，不能靠新鲜感逃避旧承诺。

## 金手指代劳

- 金手指 **不得代劳** 主角的关键抉择与情感高潮；代劳比例建议 **≤30%** 章内情节推动力。
- 系统发任务 ≠ 主角无选择；每次使用记 `resources` 代价。
- 违反 → review **StrongConstraints** blocking。

## 时间线

- 章内时间单调或明确跳跃标注；禁止无说明时间倒流。
- `timeline_events` 与正文 `when` 一致。
- 多线并行时每线标注时间点。

## 终局储备

圣经 / 总纲「终局储备」只写解锁卷号；真相细节只进 `canon/author-lore.md`。未到解锁卷：禁止揭开头号宿敌真身、打光金手指上限、或让升级线无下一档。卷纲「终局边界」与单元「禁止提前释放」是同一约束的卷/段落地。写正文不得加载 author-lore（见 KB「连载轨」）。

**锁词机器化。** 本卷之前不得出现的真名/真相词登记在 `canon/locked-terms.yaml` 的 `locked_until`（按卷）+ `compliance`（永久红线）。gate **precommit** 自动扫描正文，命中即 BLOCKING（postcommit 二次校验）。preflight CONTEXT 会自动注入本单元被锁词清单。**不要**在 Commit 日志里手写"零出现 XXX"——gate 会做。

**透支两问**（任一为「是」→ 回退改纲）：

1. 是否动用了本阶段还不该解锁的终局底牌？
2. 是否让某条升级线逼近天花板、后面没台阶接？

两问皆否时，一战多得（破境 + 缴获 + 声望）允许。多线齐涨不是透支。

## 叙事线

- 同时 **活跃主线 + 支线 ≤3** 条；新开线须有旧线收尾或降级为伏笔。
- 章纲 `forbidden` 列出本章不得推进的线。

## 人机分工（AI 辅助写作）

人定灵魂，AI 填骨架与细节。下列不得整段交给模型代决：

1. 本书读者契约与终局台阶（圣经 / 总纲）
2. 本单元主冲突、关键对白、不可逆选择
3. 伏笔开/进/关与期待债结算归属
4. 定稿润色后的「像不像这本书」——指纹优先于通用去 AI

允许 AI：章纲细化、场面填充、设定整理、审稿扫雷。**禁止**把「以下是为您润色/优化后的内容」一类指令语留进正文（见「文风与去 AI 味」）。章纲关键字段（`pleasure_point` / `hook` / 欲望阻碍）未满时，不要让 AI 先扩正文。

## 写前阻断（每章动笔前）

答不出任一项 → 先改章纲，不准开写：

1. 本章不可逆事件或压力源是什么？（前 300 字内须落到动作/对话，不是气氛）
2. 谁结算本章收益？是否仍符合读者契约四问？
3. 金手指是否代劳了关键抉择？
4. 章末切口是具体事件还是口号？
5. 与上一章同场景连写时，是否换了冲突形态或信息增量？

## 正文禁元话语

叙述层禁止作者从故事外拍读者肩膀：「卷一」「前文所述」「后文再表」「本章」「如上所述」。章号只出现在 `## 第N章` 标题，不进叙述句。

## 冲突禁话疗收束（纪律级）

当单元/章标题或细纲承诺对抗、决战、对决时，禁止用「我理解你 / 共鸣唤醒 / 融合救赎 / 不是消灭是解放」几句话让对手自行崩解或倒戈，且主角零代价。允许谈判、策反、智取，但须有可见代价、行动步骤或未完成的对抗节拍；细则与战斗章见「爽点与追读」「玄幻」「都市」。

## 高频雷点（可 gate）

| 雷 | 判定 | 处理 |
|----|------|------|
| **水文 / 注水** | 卡文或凑字时写无关痛痒段；删了故事更清楚 | blocking：砍段、加快进度，禁止定稿注水章 |
| **开篇信息过载** | ch1 堆世界观/履历/体系，无冲突无钩 | blocking（开篇期）；改露一藏九 |
| **无钩 / 口号钩** | 章末无可感知悬念或「故事才刚刚开始」 | 番茄向 ch1–3 blocking；其后 P0 文风 |
| **节奏混乱 / 冲突乏力** | 连续多章无加压、无微兑现、矛盾断链 | PacingDensity / ReaderPull；回改单元细纲 yaml |
| **爽点不足** | 开篇单元没有主爽点；其后连续单元 `pleasure` 空 | 重排单元细纲 |
| **话疗破局** | 承诺对抗的章用纯说教收冲突且无代价 | 回改；见上节 |

## 发稿前自查

低级失误在定稿前拦住，不靠发完再改：

1. 前后是否接得上（时间、伤势、已知信息、已经收过的坑）。
2. 有没有同义复读、删了故事不变的段（见「文风与去 AI 味」）。
3. 错字、病句、人设口吻串了。
4. 人物细节和情绪还在不在；中后期变水，回单元细纲 yaml，不要用改字假装修好。

```yaml
constraint_checks:

  timeline_monotonic: true
  active_plot_lines_le_3: true
  endgame_reserve_ok: true    # 透支两问皆否
  agency_settled: true        # 四问：收益回到承诺所有者
```

## Checklist

- [ ] 金手指有代价记录
- [ ] 时间线无静默冲突
- [ ] 活跃叙事线 ≤3
- [ ] 未提前动用终局储备（透支两问皆否）
- [ ] 关键节点四问可答；未无声夺走主角高光
- [ ] 无水文注水；开篇无信息过载；章末钩非口号
- [ ] 写前阻断五问可答；无正文元话语；无话疗零代价破局
- [ ] 章纲 constraint_checks 已填；人机分工未让 AI 代定契约/终局/关键对白
