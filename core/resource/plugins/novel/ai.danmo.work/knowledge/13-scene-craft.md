# 场景专项（对话 / 打斗 / 系统流）

按章合同 `beats` 标签或场景类型加载本节；不全章套用。

## 对话场景

- **性格差**：每人说话方式不同（句长、用词、回避/直给）。
- **潜台词**：表面话题 ≠ 真实诉求；避免解释型对白（角色互相讲设定）。
- **功能**：推进冲突 / 暴露信息 / 关系位移——每段对话至少完成一项。
- **节制**：网文对话占比高，但连续 5 轮无新信息 → 砍或换动作。

## 打斗 / 对决

四拍结构：

1. **态势**：谁占上风、环境约束  
2. **交换**：2–3 个有代价的攻防  
3. **转折**：规则/道具/心理破点  
4. **落点**：胜负或僵局 + 身体/资源代价  

禁止：纯招式名堆砌、无代价秒杀、战力突然跳档无铺垫。

## 系统流 / 面板

- 面板信息 **≤3 行关键数据**；其余进内心或后续章。
- 系统说话要有 **人格或机械感二选一**，勿混。
- 奖励即时但 **代价同步**（冷却、任务、暴露风险）。
- 数据流场景：数字服务情绪（压迫/兴奋），非清单罗列。
